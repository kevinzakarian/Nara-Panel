## Editing and activation

**Add option** lists every remaining property for the current object. Nested
objects, lists, maps and discriminated versions/actions have structured controls.
The JSON view supports importing or reviewing an entire record. Changes take
effect only when **Save** succeeds, which validates and applies them automatically.

The panel checks tag references and outbound cycles before activation; the core
then validates the complete server configuration, inactive listeners and managed
client exports. Invalid references, invalid core options and startup failures
preserve the previous saved model and attempt to retain/restore the running core.
Stored private keys are redacted from the general state response and retained
when a redacted record is edited. Optional keys with explicit replacement values
are updated normally.

## Builds and host requirements

The build script uses the official standard build-tag list plus V2Ray accounting,
with the upstream linker flags. Supported Linux amd64/arm64 builds include Naive
outbound via purego and install the matching `libcronet.so` from the checksum-verified
pinned Go module. Old minimal cores continue to run the original managed features;
rerun the full installer to enable the newly exposed build-dependent features.

A form exposes configuration; it does not supply third-party credentials, local
files, network connectivity, kernel modules or system privileges. TUN, TProxy,
Redirect, system VPN endpoints and network namespaces require appropriate Linux
capabilities. The default service does not grant network administration privileges;
[an optional drop-in example](deploy/network-capabilities.conf.example) is provided.
Writing NTP time needs clock-setting privileges. USB/IP/device services need their
host setup. Tor needs its external executable unless using an embedded-Tor build.
ACME and Cloudflare/Tailscale services need valid accounts, credentials and network
access. These features are not automatically enabled by the panel.

## Dashboard and update checks

The full panel version appears beneath the logo. Overview replaces the former
hero with a compact panel/core version strip. An independent background worker
checks the public panel manifest and the latest stable upstream core release every
24 hours, persists the result across restarts, and displays availability at the top
of Overview. Failures are reported as unavailable and preserve the previous known
release. No code is installed automatically and no account credentials are sent.

## Client VPN profiles and QR

Managed account exports retain the dual-stack TUN, proxied DoH, direct hostname
bootstrap and interface detection introduced in 0.2.3. The official-app QR encodes
`sing-box://import-remote-profile?url=urlEncodedURL#urlEncodedName`; a second format
provides the direct JSON URL. HTTP and HTTPS panel URLs work. Copy/PNG use the
selected format. After panel updates, refresh remote profiles or re-import local
JSON files as needed.

## Linux lifecycle manager (0.3.1)

The one-line launcher and installed `sudo nara` command update installed apt packages
before showing the manager. Options cover installation, application-only or bundled
core upgrades, status, logs, start/stop/restart, private SQLite/account/certificate
backup, admin password reset, explicit keep-data/purge removal and dedicated panel
HTTPS. Prompts retain clear `[INPUT]` markers even without ANSI color. The core build
finishes before stopping an existing panel. Full upgrades back up data and restore
application/core/environment/service files on failed readiness.

Panel HTTPS supports Caddy automatic domain certificates/renewal, one-year
self-signed domain/IP certificates and validated PEM import. Only the dedicated
NARA proxy is managed. External TCP 80/443, correct A/AAAA records and distro Caddy
packages are prerequisites for automatic issuance. Real Linux package/service
execution and public ACME issuance require a target server; local tests do not
claim to verify those environments.

## Independent subscription access (0.4.0)

Installation asks for independent webPath/panel port and subPath/subscription port.
Empty path answers generate separate eight-letter mixed-case paths; HTTP ports
default to 10000/10001. Managed Linux Settings can change all four with validation,
maintenance locking, readiness probes and rollback. The subscription listener
serves profiles and a bounded health endpoint only; panel routes are unavailable.
Managed Caddy exposes separate public TLS ports (443/8443 defaults), preserving
the two loopback backends. External proxies/containers require their own mapping.
Earlier subscription addresses must be replaced in client remote profiles.

AnyTLS uses the exact upstream nine-line padding default in managed and standalone
forms. Explicit customized schemes are retained. New inbound protocol selection
starts blank and Save remains disabled until a type is chosen. The hostname box
below the sidebar brand has been removed.
